# Worldgen Overworld : features, structures, heightmaps

Statut : brouillon
Jalon : M4
Risque : A
Règles : 96 (R1 à R96). D 30, D/S 3 (valeur lue, effet S), C 7, C sur S 5, M 0, S 51.

Troisième tiers de la génération : tout ce qui est posé sur un terrain déjà creusé et recouvert (spec `worldgen-surface-carvers.md`) : décoration par étapes (placed features, configured features, modificateurs), minerais, structures (placement, starts, références, jigsaw, anneaux des strongholds, générateurs procéduraux), heightmaps. La lumière initiale et l'ordre des statuts sont dans `worldgen-pipeline.md`.

## Périmètre

Couvre, pour `engine/worldgen` (Overworld normal) :

- les registres `worldgen/placed_feature` (273), `worldgen/feature` (240), les modificateurs de placement, les types de feature, leur rattachement aux biomes par étape et l'ordre de décoration ;
- les 30 placements de minerais classiques (étape "minerais souterrains") et la fonction de remplacement par hôte ;
- les `structure_set` (21), `structure` (52 dont 47 de l'Overworld), les algorithmes de placement `random_spread` et `concentric_rings`, le départ, les références, les `template_pool` (245), les `processor_list` (40), les gabarits `.nbt` (1511), l'assemblage jigsaw ;
- la liste des générateurs de structures procéduraux et ce qui les distingue ;
- les heightmaps : types, prédicats, usages dans la génération.

Ne couvre pas :

- l'algorithme interne de chacun des 47 types de feature utilisés (arbres, géodes, coraux...) : ils sont inventoriés ici et chacun fait l'objet d'une spec fille (liste en Questions ouvertes) ;
- le contenu de chaque générateur procédural (mineshaft, stronghold, monument, manoir...) : idem ;
- le remplissage des coffres (loot, ADR 0004) et les spawners de structures au-delà de leur déclaration ;
- l'éclairage, l'ordre des statuts, le voisinage requis : `worldgen-pipeline.md` ;
- le Nether et l'End (leurs étapes `nether_*`, `end_*` ne sont citées que pour les compter).

## Sources

- **Données extraites** (`.cache/reference/26.3/`) : `resources/data/minecraft/worldgen/{biome,feature,placed_feature,structure,structure_set,template_pool,processor_list,block_state_provider}/**` ; `resources/data/minecraft/structure/**/*.nbt` ; `resources/data/minecraft/tags/{block,worldgen/biome}/**` ; `generated/reports/registries.json` (registres de types) ; `generated/reports/biome_parameters/minecraft/overworld.json` (56 biomes du préréglage).
- **Calculs** : `wg_ref.py` (annexe de `worldgen-features-structures-vectors.md` ; sous-commandes `inventory`, `steps`, `order`, `ores`, `sets`, `structures`, `poolrefs`, `jigsaw`). Les sorties sont reproduites dans le fichier de vecteurs.
- **Documentation publique**, consultée le 2026-10-28 : Minecraft Wiki "Placed feature" (https://minecraft.wiki/w/Placed_feature, section modificateurs de placement : champs et sémantique ; la page ne dit rien de l'ordre des étapes ni de la graine des features) ; "Structure set" (https://minecraft.wiki/w/Structure_set : champs, `random_spread`, `concentric_rings`, méthodes de réduction de fréquence) ; "Jigsaw structure" (https://minecraft.wiki/w/Jigsaw_structure : champs, assemblage ; ne détaille ni les types de joint ni les noms de priorité) ; "Heightmap" (https://minecraft.wiki/w/Heightmap : prédicats ; ne dit pas quels types sont persistés) ; "Stronghold" (https://minecraft.wiki/w/Stronghold : 8 anneaux, 128 positions ; lecture tronquée à 100 000 caractères sur 175 477) ; "Chunk format" (liste des statuts).
- **Rapports locaux** (indices, rapport Overworld chapitres 2.3, 5 à 8) : chiffres déclaratifs (171, 2629, 30, 47, 18) recoupés avec les données, donc passés en C ; les passages "moteur inspecté" (formules de graine) ne sont repris que comme hypothèses S avec sonde (ADR 0002, 2b).
- **Sondes de l'oracle** : aucune exécutée (EULA non acceptée). Sondes WF (features), WT (structures), WH (heightmaps) dans `worldgen-features-structures-vectors.md`.

Convention de preuve : D, C, M, S comme dans `worldgen-surface-carvers.md`. Chaque règle S donne son comportement provisoire.

Mécanisme d'observation commun : les listes `features` et `carvers` d'un biome, les `structure_set` et les placements sont des données ; un datapack de sonde peut (a) vider les étapes, (b) ne laisser qu'une feature, (c) forcer une probabilité à 1.0, (d) imposer un biome unique (préréglage `single_biome_surface`). La sortie du serveur est alors la trace d'**une seule** feature ou structure dans un environnement connu : c'est l'unité de vérification de ce document.

### Modificateurs de placement

| Réf | Règle | Preuve |
|---|---|---|
| R16 | Un modificateur reçoit un flux de positions et produit un flux ; un résultat vide supprime la position. Les modificateurs s'appliquent dans l'ordre de la liste. Provisoire (le wiki n'énonce pas la règle de filtrage, il l'implique). | S |
| R17 | Position de départ d'une placed feature rattachée à un biome : coin nord-ouest du chunk (x et z minimaux), niveau bas du monde (page publique). Pour une feature appelée par une autre feature ou par `/place` : la position de l'appelant. | S |
| R18 | `count` : produit N copies de la position, N tiré d'un fournisseur d'entiers (0 à 4096). Plusieurs `count` successifs se multiplient. Le fournisseur est évalué **une fois par position entrante**. | S |
| R19 | `rarity_filter` (`chance` entier >= 1) : conserve la position avec probabilité 1/chance (un tirage par position). `random_chance` : probabilité flottante dans [0,1] (non utilisé). | S |
| R20 | `in_square` : ajoute à X et à Z deux entiers uniformes dans [0, 15], sans changer Y. L'ordre des deux tirages (X puis Z) est inconnu. | S |
| R21 | `height_range` : remplace Y par un tirage du fournisseur de hauteur (71 uniformes, 13 trapèzes, 2 `very_biased_to_bottom`) ; les ancres sont résolues avant (`above_bottom n` = -64 + n, `below_top n` = 319 - n). Bornes entières incluses. Trapèze : voir R41. | S |
| R22 | `heightmap` : remplace Y par la hauteur de la heightmap nommée à la colonne (X, Z) de la position (c'est-à-dire un bloc au-dessus du plus haut bloc retenu, R63). Types utilisés : `MOTION_BLOCKING` 47, `OCEAN_FLOOR` 37, `WORLD_SURFACE_WG` 19, `OCEAN_FLOOR_WG` 8, `MOTION_BLOCKING_NO_LEAVES` 3 occurrences (placed features seules). | S |
| R23 | `offset` : ajoute des tirages de fournisseurs d'entiers à X, Y, Z (-16 à 16). Ordre des tirages inconnu. | S |
| R24 | `block_predicate_filter` : conserve la position si le prédicat de bloc vrai à cette position. Prédicats utilisés : `matching_block_tag` 55, `would_survive` 54, `all_of` 28, `matching_blocks` 14, `matching_fluids` 3, `solid` 1. `would_survive` interroge la survie du bloc (spec `world-block-states.md` / M5). | D |
| R25 | `surface_water_depth_filter` (`max_water_depth`) : conserve la position si la profondeur d'eau au-dessus du sol de surface est inférieure à `max_water_depth` (page publique : "épaisseur de matériau motion-blocking sous la surface"). Inclusivité à lever. | S |
| R26 | `environment_scan` : balaie vers `up` ou `down` jusqu'à `max_steps` (1 à 32) blocs jusqu'à `target_condition` ; `allowed_search_condition` doit tenir à chaque pas ; sinon la position est supprimée. La position produite est celle de la cible. Utilisé 12 fois (lianes, dripstone...). | S |
| R27 | `count_on_every_layer` : dans le chunk, à chaque "couche" séparée par de l'air, de la lave ou de l'eau, tire `count` positions horizontales ; Y = un bloc au-dessus de la couche. Utilisé 8 fois. | S |
| R28 | `noise_based_count` : si le bruit à (x/noise_factor, z/noise_factor) est <= 0, rien ; sinon `ceil((bruit + noise_offset) x noise_to_count_ratio)` copies. `noise_threshold_count` : bruit à (x/200, z/200) ; inférieur à `noise_level` -> `below_noise` copies, sinon `above_noise` (négatif ramené à 0). Le bruit utilisé est le bruit "patch" de la décoration (nom et graine inconnus). | S |
| R29 | `surface_relative_threshold_filter` : hauteur de la position relative à la heightmap (min facultatif, max inclus) ; utilisé 3 fois (`OCEAN_FLOOR_WG`, max -13). `fixed_placement` : renvoie les positions listées qui sont dans le chunk (1 utilisation, plateforme de l'End hors périmètre). | S |
| R30 | `biome` : voir R11. Il s'applique à la position finale ; dans les 211 placed features qui le portent, il est placé à des rangs variés dans la chaîne (par exemple après `heightmap`, avant `count` dans 28 + 10 chaînes) : le rang compte parce que les positions déjà décalées sont testées. | D |
| R31 | Signatures de chaînes les plus fréquentes (53 `count > in_square > height_range > biome`, 28 `rarity_filter > in_square > heightmap > biome > count > offset > block_predicate_filter`...) : liste complète produite par `wg_ref.py chains` (FV2) ; la spec n'impose que l'ordre déclaré. | D |

### Fournisseurs

| Réf | Règle | Preuve |
|---|---|---|
| R32 | Fournisseurs de hauteur (registre, 6) : `constant`, `uniform`, `biased_to_bottom`, `very_biased_to_bottom`, `trapezoid`, `weighted_list`. Entiers (8) : `constant`, `uniform`, `biased_to_bottom`, `very_biased_to_bottom`, `trapezoid`, `clamped`, `clamped_normal`, `weighted_list`. | R33 | Fournisseurs de hauteur utilisés par les placed features : `uniform` 71, `trapezoid` 13, `very_biased_to_bottom` 2. | D |
| R34 | `uniform` entier : borne basse et haute incluses, un tirage borné (valeur = bas + tirage dans [0, haut - bas]). Les flottants `uniform` ont leur borne haute exclue. | S |
| R35 | `very_biased_to_bottom` : trois tirages uniformes emboîtés qui biaisent fortement vers `min_inclusive` (paramètre `inner` implicite). Distribution et nombre de tirages à mesurer. WF8. | S |
| R36 | `trapezoid` (hauteur) : pour des bornes entières a, b, plateau p (défaut 0) et d = b - a : si p >= d, uniforme entier inclusif ; sinon u = floor((d - p) / 2), v = d - u, Y = a + U{0..v} + U{0..u} (deux tirages, dans cet ordre : hypothèse). Pour p = 0 : triangle discret. La formule est celle du rapport Overworld 6.2 (indice "moteur inspecté") ; la documentation publique des fournisseurs de hauteur n'a pas été consultée : elle reste à confirmer, WF1 et WF8. | S |
| R37 | Les bornes d'ancres sont résolues avant le tirage et **non** ramenées au monde : le diamant triangulaire couvre -144 à 16 (centre -64), la redstone profonde -96 à -32, le fer haut 80 à 384 (centre 232), l'émeraude -16 à 480 ; renormaliser sur -64..319 est une erreur. Une position hors du monde est ignorée ensuite par la feature. | C |
| R38 | Pour un trapèze avec bornes a, b et plateau 0, la masse d'une valeur Y est le produit de convolution de deux uniformes discrètes : exemple pour le diamant (a -144, b 16, d 160, u 80, v 80) la valeur modale est -64 et la probabilité maximale 1/81 (C sur S). | C sur S |

| Réf | Règle | Preuve |

L'étape 6 compte 1635 rattachements pour 34 features distinctes : les 29 minerais, `underwater_magma`, `disk_sand`, `disk_clay`, `disk_gravel`. Pour chaque ligne : définition de feature, nombre d'essais (`count` constant, ou `rarity_filter` 1/n pour 5 placements, ou entier uniforme {0,1} pour `ore_gold_lower`), fournisseur de hauteur uniforme ou trapézoïdal, `size`, `discard_chance_on_air_exposure`. | R40 | Le nombre d'essais n'est pas le nombre de veines : ni `count`, ni `size` ne garantissent le nombre de blocs. Le rejet par l'air et les hôtes décident (R42 à R45). | S |
| R41 | Séquence de modificateurs commune des 30 placements : `count` ou `rarity_filter`, `in_square`, `height_range`, `biome`. Aucun n'utilise `heightmap` : les minerais ignorent la surface. | D |
| R42 | Une configured feature `ore` a : `size`, `discard_chance_on_air_exposure`, une liste ordonnée de `targets` `{state, target}` où `target` est un `rule_test`. Pour les minerais de roche : deux cibles, la variante pierre (hôtes `height_specific_ore_replaceables` avec `height_match` de Y >= 0, ou hôtes `stone_ore_replaceables` hors du tag précédent), puis la variante deepslate (hôtes `height_specific_ore_replaceables` avec Y <= 8, ou hôtes `deepslate_ore_replaceables` hors du tag précédent). Les bornes de `height_match` sont larges (-2032, 2031), donc le test réel est Y >= 0 pour la variante pierre et Y <= 8 pour la deepslate. Les conditions se recouvrent sur Y 0..8. | D |
| R43 | Rule tests utilisés par les minerais : `any_of`, `all_of`, `not`, `tag_match`, `height_match`, `block_match` (autres types dans le registre : `always_true`, `blockstate_match`, `random_block_match`, `random_blockstate_match`). Le test est évalué sur le bloc actuel de la position. Provisoire : pour une position et une liste de cibles, la première cible dont le test réussit fournit l'état. | S |
| R44 | Rejet par l'air, par bloc candidat qui a passé son test (rapport Overworld 6.3, hypothèse) : probabilité 0 -> aucun contrôle et aucun tirage ; probabilité 1 -> contrôle des 6 voisins sans tirage ; entre les deux -> un tirage `nextFloat` d'abord ; si le tirage est inférieur à la probabilité, contrôle des 6 voisins ; s'il y a de l'air parmi eux (l'eau n'est pas de l'air), le bloc candidat est rejeté. Le filon entier n'est pas rejeté. WF9. | S |
| R45 | Géométrie du filon, provisoire (documentation générale, à confirmer) : un segment entre deux extrémités tirées en fonction de `size`, un nombre de sphères placées le long du segment dont les rayons croissent puis décroissent, chaque bloc de la boîte englobante testé au plus une fois (mémoire des blocs déjà traités). Le rapport indique que la géométrie utilise des doubles. Aucun détail numérique n'est présupposé : WF9 compare, pour `size` 4, 9, 17, 33, 64, des filons isolés à un candidat. | S |
| R46 | Les grandes veines (cuivre, fer) et les blocs bruts ne sont pas des features : ils sont dans la règle de matière (`worldgen-surface-carvers.md` R15 à R20). Les 30 placements de ce tableau n'y touchent pas. | D |
| R47 | Distribution par biome (comptée sur les listes de l'étape 6 des 56 biomes) : `ore_clay` (46 essais) seulement `lush_caves` ; `ore_copper_large` seulement `dripstone_caves` ; `ore_copper` 55 biomes (tous sauf `dripstone_caves`) ; `ore_emerald` 10 biomes de montagne ; `ore_gold_extra` les trois badlands ; `ore_infested` 10 biomes de montagne (étape 7) ; la plupart des autres dans les 56 biomes. | C |

## Entrées / sorties

- **Décoration d'un chunk** : entrées = chunk (statut précédent) et ses voisins à portée, graine du monde, liste globale par étape (R10), grille de biomes, starts des structures, heightmaps. Sortie = blocs modifiés dans la zone 3 x 3, block entities, ticks planifiés, heightmaps mises à jour.
- **Placement d'une structure** : entrée = graine, chunk, ensembles, biomes ; sortie = départ (ou absence), puis références, puis blocs par chunk.
- **Coordonnées négatives** : floorDiv partout (R51, R62) ; les modificateurs travaillent en coordonnées de monde.

## Cas limites

- Régions autour de zéro (chunks -1, 0, 33, 34, -34, -35) pour `random_spread` (FV5).
- Hauteurs hors du monde de `height_range` (fer haut à 384, émeraude à 480, diamant à -144) : les positions sont ignorées par la feature, mais le tirage est consommé (R37).
- Une position dont le biome final n'inclut pas la feature : rejet par `biome`, mais les tirages précédents sont consommés (R11, R14).
- Structures dont l'emprise franchit une bordure de chunk : écriture seulement dans le chunk traité (R65), références à plusieurs chunks (R64).
- Chaîne de modificateurs vide (6 placed features sans modificateur) : une seule position, le coin du chunk.
- Features qui échouent (arbre sans place, veine sans hôte) : aucune écriture, mais l'aléa consommé jusqu'à l'échec est conservé (à confirmer WF6).
- Stronghold sans biome préféré proche : position initiale conservée (R59).

## Questions ouvertes

- **Ordre global des features (R10, WF2)** : étape 9 (109 features, 2991 paires non comparables) : la règle de départage décide de toute la végétation. Risque très élevé, tractable par sonde.
- **Familles de générateur et graines (R13, R14, R51, R53)** : tractables par sonde en monde à une feature (WF3).
- **Géométrie des filons (R45)** : tractable par comparaison sur des filons isolés ; si les écarts persistent, la reconstruction de la consommation aléatoire peut exiger 2a-bis.
- **Algorithme de chacun des 47 types de feature utilisés** : spec filles à écrire : `tree` (45 définitions et sous-registres : troncs, feuillages, décorateurs, racines), `simple_block`, `random_selector` et sélecteurs, `overlay`, `block_column`, `vegetation_patch`, `fallen_tree`, `spring_feature`, `disk`, `block_pile`, `huge_fungus`, `sequence`, `bamboo`, `speleothem_cluster`, `fossil`, `multiface_growth`, `iceberg`, `scattered_ore`, `root_system`, `geode`, `lake`, `monster_room`, etc. Chaque spec fille suit le montage "une feature isolée" (WF1).
- **Générateurs procéduraux (R82)** : 12 types, spec filles ; ordre de priorité : mineshaft, stronghold (portail de l'End), village (jigsaw), monument, manoir.
- **Assemblage jigsaw (R73)** : l'ordre exact des tirages pondérés et des essais est le point à lever (WT9 et WT10) ; la structure d'un village peut se comparer pièce par pièce (liste `Children` du départ).
- **Bloquants possibles pour 2a-bis** : (i) consommation aléatoire exacte des filons (R45) si la comparaison échoue, (ii) tirage dans l'assemblage jigsaw si l'ajustement d'hypothèses échoue, (iii) méthodes de réduction de fréquence legacy (R53) si l'espace d'hypothèses est trop grand. Aucun n'est démontré bloquant à ce jour.
