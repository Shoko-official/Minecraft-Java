# Entités : modèle, attributs, dimensions, physique et collisions

Statut : brouillon
Jalon : M7
Risque : A
Règles : R1 à R84 (D 12, C 1, C sur S 2, D avec sens S 5, S 62, S-arch 2)

Premier des quatre documents du jalon M7 : il décrit ce qu'est une entité (types, attributs, boîte, état observable), la façon dont elle bouge sans intelligence ni combat (gravité, traînée, friction, collisions, fluides, blocs particuliers) et la manière de la comparer à l'oracle tick par tick. Les trois autres : `entity-damage-effects.md` (santé, dégâts, effets, combat), `entity-ai-spawning.md` (IA, apparition, disparition), `entity-player.md` (joueur, faim, expérience, véhicules).

## Périmètre

Couvre, pour `engine/entity` (ADR 0004) :

- le registre des 161 types d'entité, leurs étiquettes, ce que les données extraites disent et ne disent pas d'une entité (R1 à R6) ;
- le modèle d'attributs : registre, valeurs de base, modificateurs, opérations, bornes, modificateurs portés par les objets et par les données (R7 à R18) ;
- la boîte englobante, la hauteur des yeux, les poses, l'échelle (R19 à R26) ;
- l'identité, la représentation observable (NBT), les paquets de synchronisation (R27 à R33) ;
- la place de l'entité dans le tick, le gel et le pas à pas (R34 à R37) ;
- le mouvement passif : gravité, traînée, friction, ordre de mise à jour (R38 à R50) ;
- les collisions avec les blocs et entre entités, la hauteur de pas, le sol (R51 à R60) ;
- les fluides, les échelles, la toile, le miel, la neige poudreuse, les colonnes de bulles (R61 à R68) ;
- les objets au sol, les blocs qui tombent, la dynamite, les projectiles du point de vue du mouvement (R69 à R76) ;
- l'état canonique d'une entité, le format de trace et de scénario, les règles de comparaison (R77 à R84).

Ne couvre pas :

- les dégâts, la mort, la santé, les effets de statut, les critiques et les recharges d'attaque : `entity-damage-effects.md` ;
- les objectifs d'IA, la navigation, la perception, l'apparition et la disparition naturelles : `entity-ai-spawning.md` ;
- la faim, la saturation, l'expérience, le déplacement du joueur (accélération au clavier, sprint, nage), les véhicules et les montures : `entity-player.md` ;
- les modèles, animations et sons (jalon M9) ; le détail binaire des métadonnées (`net-protocol-777.md`) ;
- les entités de bloc (`world`), les tables de butin (`loot-tables.md`).

Convention de preuve (S-arch : décision de conception, définie dans `README.md`) : D valeur lue dans un fichier extrait ; C calcul reproductible sur ces fichiers ; C sur S calcul reproductible dont une entrée est une valeur S (la conclusion reste une hypothèse) ; M observé sur l'oracle (aucun pour l'instant) ; S documentation publique seule ou hypothèse nommée H-EM. Chaque règle S porte un **comportement provisoire** et une sonde dont le critère de succès est dans le fichier de vecteurs. Les entités de comparaison sont des entités **sans IA** (`NoAI`), des objets, des blocs qui tombent, des supports d'armure, des projectiles : l'aléa n'est pas l'objet du test (docs/VERIFICATION.md, Déterminisme).

## Règles dont l'implémentation est bloquée avant mesure

Ces règles S ont un comportement provisoire nul ou non fidèle, déclaré dans leur texte : R23, R24 (hors des valeurs listées), R62 à R66 (sondes EM2, EM8). Elles bloquent le démarrage de l'implémentation de la partie concernée et le passage à `figé` tant que leur sonde n'est pas exécutée ; tout test de fidélité qui en dépend est marqué `oracle` et reste non exécuté.

## Entrées / sorties

- **Entrée d'un scénario** : description R79 ; **sortie** : trace R78.
- **Table de types** (R2, R9, R21, R22, R23) : jeu de données du projet produit par les sondes, lu à l'exécution ; schéma : (type, vivant, mob, largeur, hauteur, yeux par pose, bébé, collision avec les blocs, bases d'attributs).
- **Unités** : positions en blocs (double), vitesses en blocs par tick (double), angles en degrés (float), durées en ticks (entier).
- **Coordonnées négatives** : aucun arrondi par `floor` sur la position ; le chunk de rattachement utilise la division euclidienne (`world-chunk-format.md`).

## Cas limites

- Position exactement sur une arête de bloc ; boîte posée à cheval sur deux blocs de friction différente (R45).
- Vitesse nulle sur sol glissant ; vitesse supérieure à la largeur d'un bloc (traversée de dalle fine) ; `Motion` à ±10 (R46).
- Entité dans une colonne de lave sur une échelle ; échelle dans l'eau.
- Bloc qui tombe sur une entité ; deux entités qui atterrissent au même tick sur le même bloc.
- Entité qui change de chunk à chaque tick ; entité au bord d'un chunk non chargé.
- Attribut `scale` 0.0625 et 16 ; `gravity` négatif ; `friction_modifier` 0 et 2048.
- Désactivation de la gravité en plein vol puis réactivation.
- Entités sans IA qui reçoivent encore un déplacement de collision (H-EM26 : un mob `NoAI` garde la physique de gravité et de friction ; démenti par EM5 possible).
